# Review points

設計（upstream）レビューで確認する観点と、本プラン（`design-plan.md`）の過不足を示します。

## 確認する観点

- **失敗モード / 配信保証**: 配信先がダウン・タイムアウト・5xx のときどうするか。リトライ・バックオフ・冪等性・順序保証は。
- **後方互換 / バージョニング**: ペイロードの形が将来変わるとき、既存の受信側を壊さない方針があるか。
- **可観測性**: 配信の成功率・遅延・失敗をどう計測し、異常をどう検知するか。
- **同期/非同期の選択**: イベント処理の主経路を Webhook 配信がブロックしないか。

## 本プランの過不足

| 観点                      | 状態                                                             |
| ------------------------- | ---------------------------------------------------------------- |
| 失敗モード / リトライ     | ❌ 未記載（同期 POST・2xx 判定のみで、失敗時の挙動が無い）       |
| 後方互換 / バージョニング | ❌ 未記載（ペイロードに `version` が無く、進化方針も無い）       |
| 可観測性                  | ❌ 未記載（成功率・遅延の計測やアラートが無い）                  |
| 同期/非同期               | △ 同期 POST がイベント主経路をブロックしうる（リスクとして関連） |

## 観点

機能要件（何を送るか）は書けていますが、運用に効く非機能設計（壊れたときどうするか・どう進化させるか・どう観測するか）が欠けています。これらは実装後では修正コストが高いため、upstream で指摘します。
