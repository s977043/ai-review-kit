# レビュー観点（エージェント向け）

> **出典**: [pages/reference/review-policy.md](../../pages/reference/review-policy.md) Section 1.2 + 4.x
> エージェント・プロンプトから参照するための内部向けフラットチェックリスト。人間向けの詳細は出典を参照。

## 共通観点

| 観点           | チェック内容                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------ |
| 可読性         | 命名の適切さ、構造の明確さ、意図が読み取れるか                                                   |
| 拡張性         | 将来の変更・機能追加に対する柔軟性                                                               |
| パフォーマンス | 実行効率、リソース使用、スケーラビリティ                                                         |
| セキュリティ   | 脆弱性、データ保護、認証・認可の適切さ                                                           |
| 保守性         | デバッグのしやすさ、テストカバレッジ、ドキュメント                                               |
| 運用           | 観測可能性、障害調査のしやすさ、安全なロールアウト・ロールバック                                 |
| 計画整合性     | 計画からの逸脱とその理由が PR に記録され、レビュー可能か（大型・初見・設計判断が多い変更で確認） |

## フェーズ別の追加観点

### Upstream（設計）

- アーキテクチャ決定との整合性
- ADR との照合
- 設計意図の明確さ
- インターフェース設計の適切さ
- AI エージェント委譲 readiness（委譲前の成功基準・参照コンテキスト・レビューループ・人間判断境界の明示）

### Midstream（実装）

- コード品質と可読性
- 命名規則とスタイルガイドの遵守
- エラーハンドリングの適切さ
- 重複コードの削減
- 非同期処理の正しさ（await 漏れ・floating promise・並行競合。並列化の効率提案とは区別する）

### Downstream（テスト/QA）

- テストカバレッジ（正常系/異常系/境界）
- エッジケースのテスト
- テストの可読性と保守性
- テスト実行時のパフォーマンス

### ドキュメント変更（doc-only / #1068）

差分が `*.md` / docs 配下のみの PR では、コード観点（特に Downstream のテスト）が空振りし、ドキュメント固有の実害を拾えない。以下の専用観点でレビューする:

- **リンク切れ**: 内部相対パス・アンカー・外部リンクが有効か
- **正本整合**: 設定ファイルや実装と矛盾する記述がないか（例: 設定値とドキュメント記載の乖離）
- **版数・件数・日付のずれ**: 実態と一致しているか
- **実行例の到達性**: 記載したコマンド・エンドポイント・パス・オプションが実在し到達可能か

### 運用・出荷影響（Operations / #1196 S1）

本番運用・障害対応・ロールアウトに影響する変更で確認する。インフラ・スキーマ・設定・公開 API・課金・認可に触れる差分では特に重視する:

- **観測可能性**: 障害時の原因調査に必要なログ・メトリクス・トレースが出るか（過剰・不足の両方）
- **秘匿情報の漏洩**: ログ・エラーメッセージ・トレースに秘密情報や個人情報を出していないか
- **ロールバック**: 問題発生時に安全に戻せるか（後方互換、データ移行の可逆性）
- **マイグレーション安全性**: 破壊的スキーマ変更・大規模 backfill・ロック影響・段階適用の要否
- **段階的ロールアウト**: feature flag / カナリア / 段階公開が必要な規模・リスクか
- **障害時の影響範囲**: 失敗が他サービス・他チーム・既存利用者に波及しないか
