### 1. `set -e` は条件部と関数呼び出しで無効になる

PR #2090 round 2 は `DISPOSITION_CHECKS=$(… || true)` の `|| true` を外し「jq 失敗 → exit 2」に写した。しかし `judge_pr` は `if judge_pr "${pr}"; then` から呼ばれ、bash では `if` の条件部で実行される関数の内部では errexit が抑止される。`$(...)` 内の `exit 2` はサブシェルを抜けるだけで本体は続行し、`checks_json` が空のまま verdict merge になった。オーガナイザーはレビュアーの修正案を bash の意味論を確かめずに受理し、#2090 の敵対レビューも「`|| true` 除去で exit 2 に写る」を実測せずに閉じた。

PR #2109 で `|| return 2` を全読み取りに付け、呼び出し側は `judge_pr && rc=0 || rc=$?` で受けて `case` で分岐する形に直した。修正の検出力は「読み取り失敗 → `gh pr merge` 不到達」を stub の calls.log で固定するテスト 3 件で担保した。`worker-discipline-template.md` へ、write op を持つ script は失敗注入テストで担保する、を追記した。

### 2. artifact / record の形を変える PR は schema を同 PR に含める

PR-3 の委託プロンプトは `schemas/**` を「触らない」に入れていた。artifact に新キーを足す変更は公開契約の変更であり、schema が追随しなければ利用者の schema 検証が落ちる。境界を狭くしたのはオーガナイザーで、ワーカーは指示どおり報告に留めた。`worker-discipline-template.md` へ、形を変える PR は schema を同 PR に含め、schema は Always-ask で確認する、を追記した。
