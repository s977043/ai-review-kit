### 1. パイプの早期クローズは `pipefail` の下で終了コードを書き換える

`find | sort | head -n "$drop" | while ...` の `head` は `drop` 行を読んだ時点で終了する。`sort` の出力がパイプに残っていれば `sort` は SIGPIPE で死に、`pipefail` がその値をパイプライン全体の終了ステータスにする。`set -e` により、スクリプトは末尾の `exit 0` へ到達しない。パイプのバッファ長がプラットフォームで異なるため、Linux では顕在化しないことがある。

修正では `head` を使わず、ループの中で数えて `drop` を超えたら `continue` する形にした。`continue` は読み取りを続けるので `sort` は必ず書き終える。**`break` では直らない**。ループを抜けた時点でパイプの読み口が閉じ、同じ SIGPIPE が起きる。

最初に試した「コマンド置換で一覧を受けて here-doc でループへ流す」形は、200 件の一覧でデッドロックした（20 秒でタイムアウト）。この経路は採らないことをコード内のコメントに残した。

### 2〜3. base と突き合わせる規律が無かった

2 はオーガナイザー、3 はワーカーの問題だが、いずれも「変更後だけを測って変更前を測らない」という同じ形である。`worker-discipline-template.md` へ 2 項目を追記した。エラーを返していた入力・空の結果を返していた入力・対象が存在しない入力の 3 つは修正で例外に変わりやすい、という具体を添えている。

### 4. 別ランタイムの制約は委託前に確かめる

Codex のサンドボックスはネットワークが遮断されており、`npm ci` が `@types/js-yaml` の `ENOTCACHED` で失敗する。その後 `ajv` 不在で全体 setup が失敗し `# pass 0 / # fail 889` になる。これを回帰と読まないための注記と、オーガナイザー側で `npm ci` を済ませた worktree を渡す手順を `worker-discipline-template.md` に追記した。worktree の `index.lock` を作れず commit できない点も同じ節に書いた。

### 5. 行き止まりも記録する

`.plugin-scanner.toml` を PR 自身が編集して finding を抑制できる、という論点に対し CODEOWNERS 方式を 2 回検討して 2 回とも同じ結論に達した。`.github/CODEOWNERS` は `* @s977043` を割り当てているが、`required_pull_request_reviews` が null で強制力が無く、著者と唯一のオーナーが同一のため成立しない。この結論を carry-over へ記録し、次回は別の機構から検討を始められるようにした。
