## うまくいったこと

### 変異注入がテストの空振りを 3 回検出した

追加したテストに違反を注入して `# fail` が増えることをワーカーへ義務づけた結果、**注入して初めて分かった穴が 3 件**出ました。いずれもテスト自体は書かれており、注入なしなら緑のまま通過しています。

- severity 規則の二重ガード `rows.length >= 2` が `| blocker | critical |` 1 行だけの複製を見逃していた
- false-positive 用 fixture が allowlist を経由しておらず、verdict allowlist を形状規則へ戻す変異が生存した
- `--base` の trim 検査が、trim あり・なしの双方で exit 1 になるため区別できていなかった

3 件目はワーカー自身が「最初のテストでは捕まえられず、注入して初めて気づいた」と報告しています。**テストがあることと、テストが失敗を捕まえることは別**という `improvement-flow.md` の記述が、そのまま実証された形です。

### 対照実験がアサーションの無効性を証明した

Copilot から「`byId.set(pin.id, pin)` は後勝ちなので重複 id を検出できない」という指摘が入りました。ワーカーは修正するだけでなく、**旧アサーションに重複を注入すると `# pass 51 / # fail 0` で緑のまま通る**ことを対照群として実行しています。指摘が正しいことを主張ではなく実行で示した例です。

### 範囲 diff のレビューが per-PR レビューの後で major 2 件を出した

per-PR レビューを 11 本通した後、範囲 `ae597652..2c537597` に対する多視点レビューを実行したところ、**path traversal と ReDoS の 2 件**（どちらもセキュリティ）が新たに出ました。いずれも個別 PR では構造的に見えません。

- **traversal**: 同じファイル内で RA-2 は `path.posix.normalize` による封じ込めを実装済みなのに RA-1 だけが素通し。**2 つの検査を並べて見ないと気づけない**
- **ReDoS**: 正規表現単体は正しく、必須チェックの `timeout-minutes: 10` と組み合わせて初めて攻撃面になる

### 公開契約 PR のレビュー 2 本が 3 巡目まで価値を出した

`--base` の PR は 4 巡しました（初回 2 本 + 再レビュー 1 本 + bot）。指摘は「機能の欠落」→「文書と実装の乖離」→「1 経路だけの取りこぼし」と移り、**2 巡目で「修正が元の Issue とまったく同じ silent failure を新しく作っている」を検出**したのが最大の収穫です。`--base` が明示 artifact を無警告で捨てる形と、解決できない ref が silent `no-changes` になる形の 2 件で、レビュー無しなら Issue を閉じて同型の Issue を起票し直すことになっていました。

### 1. リポジトリ実体に依存する自己整合テスト

RA-1 検査の観測モードを検証するテストが、**リポジトリの実体に「違反がちょうど 1 件ある」ことを pin**していました。承認済みの 1 行を適用して違反を 0 件にした瞬間、必須チェック `Unit tests (22.x)` が `# fail 1` で落ちています。

このコミットを適用したのはオーガナイザー自身です。ワーカーの権限では `.claude/**` を編集できなかったため引き取ったもので、**修正が正しいほどテストが壊れる**構造でした。解決は期待値の書き換えではなく、**注入 fixture と純関数への pin し直し**です。

### 2. `\b` は CJK に語境界を作らない

証跡要件の検出規則が `/(?<![A-Za-z0-9_])findings?(?![A-Za-z0-9_])|指摘/` ではなく `/\b(?:findings?|指摘)\b/` の形で書かれており、`指摘` の枝が**日本語の実文で一度も発火しません**。棚卸し記録の宣言表は「検出できる」と書いていました。fixture が英語 `finding` だけを使っていたため、テストもこの枝に一度も触れていません。

日本語主体のリポジトリで日本語語彙の正規表現を書くときの定型的な事故です。

### 3. 生の NUL バイトでファイルが grep から消える

`normalizeSeverity('\0not-a-severity')` と書いたつもりが、**エスケープ列ではなく 1 バイトの制御文字**になっていました。`file` が `data` と判定し、grep がファイル全体を走査対象から外します。

機能は正常（NUL も単なる 1 文字）なので、`npm test` / prettier / markdownlint / textlint / `meta:validate` がすべて素通ししました。発見のきっかけは、オーガナイザーが `grep -n "ra1Sink"` を実行して空が返り、`node -e` で読んだら存在したことです。ワーカー側は同じ現象を「shell の grep が壊れている」と誤診し、以後 `node -e` へ切り替えていました。**観測の異常を環境へ帰属させる前に対象ファイルを疑う**という規律の不在です。

なお本セッション後の調査で、`tests/cli-promote-propose.test.mjs` にも同型の生 NUL が既に存在することが判明しました（意図的なテストデータだがエスケープでなく生バイト）。#2055 で機械検査へ落とします。

### 4. パイプ越しの `$?`

`npx textlint --no-cache <file> | tail -5` の直後に `$?` を読むと `tail` の終了コードが返ります。ワーカーは textlint を exit 0 と報告しましたが、実際は exit 1 でした。「Run before claiming」を満たしたつもりで満たしていない形です。

### 5. 委託の境界を絞りすぎて正しい修正を塞いだ

ADR の編集範囲を「『現在の検証手段』列のみ」と指定した結果、**同じファイルの Context 節にある同種の行番号ずれ**が直せませんでした。ワーカーが「スコープ外」と正直に報告したため拾えましたが、報告がなければ事実誤りが残っています。

**前のウェーブでも同型が起きています。** `schemas/review-intent.schema.json` の編集を禁じた結果、`stage` の enum が閉じていて upstream flow に Intent を付けられなくなり、後から制約を解きました。

境界は「触ってよい範囲」を書くためのものですが、「触るな」を書きすぎると**タスクの完了に必要な修正まで塞ぎます**。

### 6. ローカル Node の版ズレによる偽 red

ローカルが v26.0.0、`.nvmrc` が 22.22.2 の状態で `tests/agent-skill-bridge.test.mjs` の YAML golden 2 件が落ち、ワーカーが「main 側の既存 red の可能性」と報告しました。`yaml` の版はロックファイルと一致していたため、直接依存の版突き合わせだけでは切り分けられません。決め手は**同一 SHA の CI conclusion**でした（workflow の conclusion は全ジョブ成功が条件なので、同じ commit が `success` なら CI 側の Node では通っている）。

## 運用メモ

- **dist-bot stall が 3 回発生**しました。`gh run list --commit <40 桁 SHA>` が全 run `action_required` / `0s` を返すのが signature です。release は `scripts/release-please-kick.sh`、通常 PR は**ワーカーが次のコミットを push すれば発火**します
- **release PR は他 PR をマージするたび作り直されます。** kick 前に `gh pr view <N> --json headRefOid` で現 head を測ってください。前回測った SHA は既に古い可能性があります
- `--paginate` と `--jq '...|length'` を組み合わせると**ページごとの件数**が返ります。合算しないと最初のページの件数を全体と誤認します（本文書の測定コマンドは `paste -sd+ - | bc` で合算しています）
