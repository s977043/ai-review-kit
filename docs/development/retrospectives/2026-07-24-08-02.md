### 1. 監査の看板数値

報告した 3 つの数値のうち、再現できたものはありませんでした。

| 当初の報告                                             | 実測                                                                                                                                              |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 機械検証参照の乖離率 0.18%（母集団 1123 + 340 = 1463） | 864 件中 0 件。0.18% は 2/1123 とのみ一致し、併記した母集団ではどの整数分子でも再現できない                                                       |
| 人手列挙は 20 件中 18 件（90%）が陳腐化                | spec 化した 4 件のうち 2 件。20 件の抽出方法が記録されておらず再現できない                                                                        |
| チェックリストが 37〜41 日無視された                   | 欠落期間 41 日（#1251）と 37 日（#1309）は正しい。ただしチェックリスト #1442 のマージは 2026-07-08 で、項目が存在しながら守られなかったのは 25 日 |

根本原因は、委託した監査の集計値を測定コマンドごと確認しないまま公表した点です。発覚はレビュー 4 層目でした。それまでに数値は 3 ファイル、マージ済み PR、ユーザー報告へ伝播していました。

対応として、#1730 で分子と分母を併記し、再実行できるコマンドを `doc-enumeration-checks.md` へ記載しました。再現できない集計値は、`git diff` で追える具体例へ置き換えています。

### 3. 文書化した手順の未実行

同じクラスが本ウェーブで 2 回起きました。`doc-enum:ignore` の緊急回避手順と、`git pull --rebase` の許可行です。どちらも手順として書かれていました。ただし著者と後続のレビュー層のいずれも、一度として実行していません。

`git switch -c <branch> origin/main` で作ったブランチは upstream が origin/main になります。そのため `git pull --rebase` は main へのリベースとして働きます。push 済みコミットが書き換わり、次の push は reject されます。結果として、同じ項目が禁じる force push を必要とする位置へワーカーを追い込みます。レビュアーが実 git で再現しました。
