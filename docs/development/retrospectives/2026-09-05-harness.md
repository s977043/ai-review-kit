### 1. 並行実行で常に落ちるテストは flake ではなく欠陥

`tests/cli-ensemble-flag.test.mjs:115` は `os.tmpdir()` 全体の `river-ensemble-*.md` を 0 件と assert する。`tests/cli-option-consumer-check.test.mjs` の `before()` が 31 面に `--ensemble` を付けて `parseArgs` を走らせるため、同一 runner で同時実行すると `26 pass / 1 fail` になる（範囲レビュー C 視点、オーガナイザー再現）。本セッションでは並行して走る worker の `npm test` が互いの残骸を数え、6 回落ちた。#2087 の finding 3 として起票済みで、本振り返りの B 項目として修正 PR を委託した。

### 2. 共有データ形は producer の実物でテストする

PR-2（resolver）は PR-1（registry）の `triggers` を引数注入で受け取る設計なので、PR-1 の完成を待たずに実装できた。しかし PR-2 の fixture は設計案の形（`requiredEvidence: ['subjectRevision']`）で書かれ、PR-1 の実物（`['tasks','diff']`、8 語 enum）とズレた。#2093 のレビューが「両方マージすると PR-2 のテストが落ちる」を実測し、PR-2 の round 2 で PR-1 のブランチから実物を持ち込んで 34/34 を確認した。並列委託で共有データ形を触るときは、consumer 側の PR に「producer ブランチの実物で通る」実測を必須にする。`worker-discipline-template.md` へ追記した。

### 3. 自分の振り返り doc も未検証の出典になる

`retrospectives/2026-09-04-05.md` は untracked の `skills/agent-skills/as-*` 5 件を「`npm ci` 由来」と書いた。#2091 のワーカーが Node 22.22.2 で `npm ci` を実行した基準線は 0 件で、レビューも同じ結果だった。5 件の由来は未特定である。振り返り doc は「観測した時点の推定」を含むため、後続 doc が引用するときは再現してから使う。該当箇所に訂正注記を入れた。
