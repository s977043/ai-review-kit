### 1. 読み取り専用の指示は CLI の副作用を縛らない

レビュー agent は後方互換の検証のため `git archive 95e20e82` で旧版 CLI を展開して実行した。旧版ではまだ exit 0 だった `skills import` / `skills export` / `feedback add` / `suppression add` が成功し、展開先ではなく現在の作業ツリーへ書いた（`skills/agent-skills/as-*` 134 ディレクトリ、`.agents/`、`.river/feedback/2026-09.jsonl` と `.river/memory/index.json` に各 1 エントリ）。「ファイルを編集しない」はエディタ経由の編集しか縛らない。

`worker-discipline-template.md` へ 1 項目追記した（#2077）。

### 2. 免責文言はレビューで検証されにくい

免責は「この変更は破壊的でない」という PR 自身の主張であり、レビュアーはその主張の前提（挙動が変わらない）を実測せずに読む。#2073 では「その面での動作は変わらず」と書かれたが、実測は当該面の実行自体が行われない。

`docs/governance.md` の「Breaking change の扱い」に、免責を追加・拡張する PR は挙動を変更前後で実測し PR 本文に併記する、を追加した。

### 3. `gh pr checks` は同名 check の全 run を並べる

`gh pr checks` は同じ head に対する全 run を返す。test.yml は `concurrency: ci-${{ github.ref }}` / `cancel-in-progress: true` なので、再実行や再トリガーがあると `cancel` の古い run と `pass` の新しい run が同名で並ぶ。#2068 の head で `river-review` が 2 行（`pass@10:34:14` / `skipping@10:34:12`）並ぶことを実測した。

一方 `scripts/wait-pr-ready.sh` が使う check-runs API は既定 `filter=latest` で最新 run しか返さない（92ad9c15 で既定 22 件 / `filter=all` 23 件を実測）。誤読が起きたのは `gh pr checks` を直接読む経路だけである。

`/merge-check`（`.claude/commands/merge-check.md`）と `docs/governance.md` の `gh pr checks` に `group_by(.name) | map(max_by(.startedAt))` を入れ、同名 check の最新 run だけを見るようにした。#2068 で `river-review pass` の 1 行になることを確認した。

### 4〜6. 既存ガードの再発

4 は memory `feedback_zsh_no_word_split_file_loops`、6 は CLAUDE.md「Fact-check what you author」に既にある。新しい規律を足しても再発は防げないため、本書に再発として記録するにとどめる。5 は単位の問題で、`heuristic-detector-checklist.md` §1 へ「位置を報告するときは単位を明示する」を追加した。
