PR #1752 のマージから #1761 のマージまでは 5 時間 19 分 23 秒です。#1752 が対象とした事象は、その対策のマージ後に再発しました。

読む側が読むことを前提とした仕組みは、読まない経路が 1 つでも残っていれば破れます。マージ操作の直前にチェックリストを読む経路と、読まずにマージする経路の両方が存在したため、後者を通った 1 回で対策は無効になりました。#1770 でラベルの有無を CI の成否へ写像し、必須ステータスチェックへ登録して初めて、後者の経路そのものが消えています。

### 2. 機構化した対策自体が副作用を持った

追加した workflow（#1770）には、次の concurrency 設定があります。

```yaml
concurrency:
  group: blocked-label-guard-${{ github.event.pull_request.number }}
  cancel-in-progress: true
```

PR #1776 で同一 head SHA に対して 2 つの run が同時に発火し、片方が cancel されました。`Blocked label guard` は必須ステータスチェックであるため、`cancelled` の check-run が残った結果として `mergeable_state` は `blocked` のままになります。他の必須チェック 6 件はすべて pass しており、`behind_by` も 0 でした。原因が「ラベルが付いている」ではなく「run が cancel された」ことなので、エラーメッセージからは理由を読み取れません。自動では解消せず、`gh run rerun` による手動介入を要しました（#1778 で追跡）。

マージ事故を止めるために入れた gate が、別の形でマージを止めています。gate の追加時に「この gate が誤って止めるケース」を洗っていれば、`cancel-in-progress` と required check の組み合わせは設計時点で候補に挙がったはずです。

### 3. 同一箇所の連続変更が回帰を生んだ

`src/cli.mjs` は 7 コミット連続で変更されました（#1735 → #1746 → #1753 → #1757 → #1761 → #1769 → #1777）。このうち 2 回がリリース済みの回帰です。

| 回帰 | 出荷リリース | 内容                                                    | 修正  |
| ---- | ------------ | ------------------------------------------------------- | ----- |
| W1   | v1.72.0      | フラグ先行（パス後置）形が余剰 positional として exit 1 | #1753 |
| B1   | v1.72.1      | `--phase Upstream` の大文字入力が exit 1                | #1757 |

いずれも根本原因は同じです。canary の正常系テーブルに「その書き方」が 1 行も無く、変更が壊した範囲を検出できませんでした。canary 自身のコメントが記録しています。

- W1: 「上の 28 行はすべてパス先行（`run . --dry-run`）だった」ため、フラグ先行順の回帰を「1 行も検出できなかった」（`tests/cli-usage-error-exit-codes.test.mjs:1321-1324`）
- B1: 「`--phase Upstream` は v1.72.0 まで exit 0 で、`normalizePhase` が小文字化して upstream として正しく機能していた」。見逃した原因は、大文字入力のケースが canary と既存テストのどちらにも無かった点である（同 `:1329-1333`）

同じ構造が CI 側でも起きました。`.github/workflows/test.yml` は #1773 → #1774 と連続で変更され、#1773 のマージ後の敵対的レビューで、バイト比較 `git diff --quiet` が untracked な ncc chunk を見ないことが判明しています。#1773 が作った欠陥ではありませんが、#1773 が当該検証へ流す PR を増やしたため、そこが主要防御線になっていました。

連続変更に共通する落とし穴は、直前の変更が pin した範囲を確認せずに次の変更へ着手する点です。pin されている範囲の外側は、変更してもテストが緑のまま通ります。
