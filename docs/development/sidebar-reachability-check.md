# sidebar 到達性の機械検証

`scripts/check-sidebar-reachability.mjs` は、公開対象の日本語ページが `sidebars.js` のナビゲーションから到達できることを検証します。単体実行は `npm run check:sidebar-reachability` です。`npm run meta:validate` からも呼ばれるため、CI の必須チェック `Meta consistency` が落ちれば PR はブロックされます（#1726 と同じ接続）。

## なぜ script なのか

`sidebars.js` は Docusaurus の `autogenerated` を使わない完全手書きです（#1727）。そのため sidebar に列挙しなかったページはナビゲーションに現れません。Link Check（lychee）はリンク切れを検出しますが、「どこからもリンクされていない」状態は検出しません。書いたのに載せ忘れる失敗が構造的に起きやすいため、[improvement-flow.md](./improvement-flow.md) の「mechanical に検証できるか」基準に従い、script と CI に倒します。

以下は 2026-08-02 時点の実測値です。数値を更新するときは、同じコマンドを実行して出力から転記してください。

| 区分                            | 件数 |
| ------------------------------- | ---- |
| 公開対象の日本語ページ          | 101  |
| sidebar 掲載                    | 53   |
| allowlist 登録（PR B で仕分け） | 48   |

分子 2 つは `npm run check:sidebar-reachability` の OK 行が出力します（`53 page(s) in sidebar, 48 allowlisted`）。分母は次のコマンドで数えられます。

```bash
find pages -name '*.md' -not -name '*.en.md' | wc -l
# 出力: 101
```

issue #1727 の起票時の実測は「sidebar 掲載 50 / 未掲載 51」でした。差分は測定方法の違いです。本 checker は Docusaurus と同じ規則で frontmatter `id` を解決します。たとえば `pages/use-cases/index.md` は `id: use-cases-index` という ID で sidebar に掲載済みのため、未掲載には数えません。

## 対象の決め方（列挙の契約）

分母となる「公開対象の日本語ページ」は、次の決定論的な規則で列挙します。

- `pages/**/*.md` を再帰的に列挙する。ただし `*.en.md`（英語ページ）は除く
- パス segment が `_` で始まるファイル・ディレクトリは除外する（Docusaurus docs plugin の既定 exclude と同じ。partials 用）
- frontmatter に `draft: true` または `unlisted: true` を持つページは除外する（Docusaurus 標準の非公開機構が既にあるため、sidebar 掲載を要求しない）
- doc ID は「`pages/` からの相対パス（拡張子なし）」とし、frontmatter `id` があれば最後の segment を置き換える（Docusaurus の ID 解決と同じ規則）

英語ページ（`*.en.md`）は対象外です。現行の sidebar は日本語ページのみを列挙する設計であり、issue #1727 の実測も日本語のみを分母としています。英語側のナビゲーション設計は PR B 以降の情報設計で扱います。

## 何をエラーにするか

- 未掲載かつ allowlist 未登録のページがある
- allowlist エントリの理由が空、または文字列でない（理由なしの黙殺を作らない）
- allowlist エントリのページが sidebar に掲載済み、または存在しない（期限切れの除外。放置するとページ復活後も検査されないままとなる）
- `sidebars.js` が実在しない doc ID を参照している
- 複数ページが同じ doc ID に解決される
- 日本語ページまたは sidebar の doc ID が 1 件も取れない（列挙・抽出の空振りを OK にしない）
- `sidebars.js` に未知の item 形状がある（黙って読み飛ばすと配下の doc が誤検出されるため throw する）

## 未掲載を許可する手順（allowlist）

意図的に sidebar へ載せないページは、`scripts/check-sidebar-reachability.mjs` の `SIDEBAR_ALLOWLIST` に「doc ID → 理由」で登録します。理由は必須です。理由の検証は `check-doc-enumerations.mjs` の `resolveIgnoreKeys` を import して同じ実装で行います。

```js
export const SIDEBAR_ALLOWLIST = {
  'reference/internal-design-notes': '内部設計メモのため意図的に未掲載',
};
```

逆に、ページを sidebar へ載せたときは同じ commit で allowlist から削除します。残すと期限切れエラーになります。

初回登録（#1727 PR A）は、現状の未掲載 48 ページ全件を「PR B で仕分け予定」という暫定理由で登録しています。「載せるべきなのに載っていない」か「意図的に載せない」かの仕分けと sidebar への追加は PR B のスコープです。

## 誤検出が出たとき

false positive でメイン開発を止めないことを最優先とします。

1. 列挙・抽出の規則（`listPublishedJaPages` / `collectSidebarDocIds`）を直して、正しく判定できるようにする
2. すぐ直せないなら `SIDEBAR_ALLOWLIST` に理由付きで登録し、issue を立てる
